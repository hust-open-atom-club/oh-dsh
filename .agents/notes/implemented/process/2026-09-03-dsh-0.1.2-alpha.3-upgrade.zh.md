# Agent Note：将固定的 DSH 运行时升级到 0.1.2-alpha.3 线

状态：已实施

[English](2026-09-03-dsh-0.1.2-alpha.3-upgrade.md) | 中文

## 问题

固定运行时停留在 `0.1.1-rc.2`（npm `latest` 标签）。0.1.2 线移动了
Oh-DSH 依赖的四项契约：`@deepseek-ai/dsh-client-runtime` 已移除（store
引擎迁入 `dsh-client-store`，由 shell 内核静态表提供，与 `cordis`
相同）；slot 系统将会话作用域子槽改为严格模式（出口必须由当前会话
Provider 包裹）；settings 远程从 `dsh-host-apiproxy` 迁入
`dsh-api-settings-controller`；web 服务器用启动令牌交换会话 cookie 的
方式把 UI 关在门后。

最新发布 `0.1.2-rc.1`（2026-09-03 发布）从 `dsh-session` 移除了
`Session.events` getter。所有已发布的 dsh-TUI 都读取 `session.events`
（channel/plugin/promptDebug），包括 v0.10.0-beta.4 及其 main 分支——
TUI 类型检查在 rc.1 下出现约 50 个 TS2339 错误，运行期该属性也已不存在。
`0.1.2-alpha.2`（TUI 自己声明的验证线）不可安装：装配的 devDependencies
引用了三个从未发布的 `dsh-experimental-*` 包。alpha.4/alpha.5 同样移除了
`Session.events`。

## 决策

- 钉住 `0.1.2-alpha.3`——最新可安装且 dsh-TUI v0.10.0-beta.4 可编译运行
  的版本（alpha.3 仍带 `Session.events`；alpha.4 在 beta.4 发布之后）。
  rc.1 升级在 dsh-TUI 发布 Session-projection 适配后解锁；每日上游
  watch 会持续标记更新的版本。
- 跟随已发布的表面依赖：dsh-TUI 子模块 → v0.10.0-beta.4（嵌套 dsh-auth
  → 4e7cba3 "support dsh 0.1.2-alpha.1"，ecosystem-spec → d28c267），
  Better Sidebar → v0.18.0-alpha.0（上游自己的 "DSH 0.1.2-alpha.x only"
  版本；v0.17.1 仍在导入已移除的 `settingsNamespace`），dsh-context →
  v0.41.0。
- 对已发布装配中无法解析的 devDependencies，在 `resolveNpmAssembly()`
  中剥离（装配只被 `pnpm install --frozen-lockfile` + `deploy --prod`
  消费；dev 依赖从不进入 staged 运行时）。运行时锁文件的生成将全部
  `@deepseek-ai/dsh-*` 闭包成员钉在线版本上——否则 pnpm 会把
  `^0.1.2-alpha.3` 范围解析到最新预发布（今天是 rc.1），悄悄混合发布线
  ——staging shim 则逐字镜像锁文件自身记录的 overrides（pnpm 拒绝
  frozen 安装中记录的 overrides 与当前配置不一致）。生成脚本存放在
  本次升级的审计目录。
- 根工作区为 TUI 的宽联合范围（`^0.1.0-rc.6 || ^0.1.1-rc.1 ||
  ^0.1.2-alpha.2`）携带同样的钉线 overrides，镜像上游 dsh-TUI 工作区
  自己携带的 override 块；否则 pnpm 在 0.1.2 线上无法解析这些联合。
- 在最窄接缝适配客户端契约：所有 `dsh.client.inject` 清单移除
  `@deepseek-ai/dsh-client-runtime`；skins/sidebar/desktop-frame 改从
  `@deepseek-ai/dsh-client-store` 导入 `defineStore`（由 shell 静态表
  解析，与上游自己的客户端 bundle 引用方式一致）；desktop-frame 用
  标准 `SessionProvider` 共享包裹严格的会话作用域 `details` 出口；
  设置命名空间边界补丁重新锚定在 `dsh-api-settings-controller`（同样
  的白名单语义）；两个 smoke 完成启动令牌到会话 cookie 的交换，并对
  传输失败重试一次（0.1.2 服务器关闭空闲 keep-alive 连接，undici 不会
  重放非幂等请求）；smoke-client 合成器选择器跟随 0.1.2 DOM（工作区
  主选择器是 `role=textbox` div，合成器输入是带 `data-phase` 的
  contenteditable div）。
- 0.1.2 loader 不再激活在另一个 inject 回调里创建的嵌套动态
  `ctx.inject`。skins 与 plugin-marketplace 因此按载体注册并列的一级
  注入（浏览器表面为 surface+webServer，TUI 调色板仅 surface，TUI 斜杠
  命令为 surface+commands），模块级 `inject` 数组刻意留空——dsh-auth 的
  模式，避免过期 patch 把新启动锁死。
- 移除内置 `@oh-dsh/vision` 桥接插件：DeepSeek V4 Flash 原生多模态，
  DSH 原生 attachment rail（粘贴、缩略图、提交）与模型无关，桥接存在
  的意义只是为纯文本模型描述图片。smoke 的贴图探针保留——它断言的是
  原生附件流程（vision→attachment 更名），现在反而更重要。
- 浮动 chrome（置顶摘要、marketplace 表面）锚定在共享 chrome 层
  （`plugins/shared/chrome-layer.ts`）内：该层覆盖内容区域并统一扣除
  标题栏高度，浮层只用简单的绝对定位角偏移，不再各自用
  `--oh-dsh-titlebar-height` 重推视口坐标。模态对话框降级作用于该层
  （两个浮层共享其堆叠上下文），取代逐面板的降级条目。

## 后果

- 三个表面运行在同一个自洽的 0.1.2-alpha.3 树上（557 个解析包，frozen
  安装）。已验证：typecheck、297 个单元测试、frozen staging、桌面与
  web smoke 通道（客户端图、原生图片附件、skins 偏好持久化、marketplace
  快照、sidebar Files/Git API、PTY 终端执行）以及 TUI 启动器帮助。
- rc.1/alpha.4/alpha.5 仍被 dsh-TUI 的 Session-projection 适配阻塞；
  之后升级只是一次钉版加上上述锁文件再生成流程。
- 六个 nix 固定输出哈希已刷新，并通过 Linux nix runner 上的真实
  `nix build .#oh-dsh-tui-pinned` 验证（临时 CI workflow 完成，取值落地后
  已删除）。Nix 运行时 shim 与 staging 完全对齐：把提交的锁文件自身的
  overrides 段复制进装配的 pnpm-workspace.yaml、在锁文件旁提供剥离
  devDependencies 的 manifest、安装阶段兼容 0.1.2 装配不再携带 config/
  目录。
- npm 的 `@deepseek-harness-tui/dsh-auth@0.1.0`（Nix 发行工件）是
  2026-08-24 的 fba02bc 构建；beta.4 的嵌套 gitlink 4e7cba3 未发布，
  在上游发布之前，staged 运行时与 Nix 装配携带不同的 dsh-auth 构建。
- web 服务器令牌交换意味着任何外部客户端在调用 API 之前必须先完成
  cookie 铸造。

## 考虑过的替代方案

**钉 rc.1（最新发布）。** 否决：没有已发布的 dsh-TUI 能在它上面运行
（`Session.events` 已删除）；适配约 50 处渲染器调用意味着修改被固定的
子模块，违反 pinned-source 规则。

**钉 alpha.2（TUI 声明的验证线）。** 否决：按发布态不可安装（存在未
发布的 `dsh-experimental-*` devDependencies）。

**保持 0.1.1-rc.2 只升插件。** 否决：每个 0.1.2 线的插件发布都以
0.1.2 运行时为 peer；表面与运行时会分裂，正如 0.1.1-rc.2 笔记警告的
那样。

**保留 vision 桥接与原生多模态并存。** 否决：V4 Flash 直接消费图片后，
桥接只是增加第二条描述路径和一个强制智谱 Key，没有能力增益；移除还
顺带清掉它的设置命名空间与凭据处理。
