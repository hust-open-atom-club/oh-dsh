# Agent Note: DSH 0.1.5-rc.1 upgrade

Status: implemented

English | [中文](2026-09-11-dsh-0.1.5-rc.1-upgrade.zh.md)

## Problem

The 0.1.5-rc.1 release line ships the DeepSeek V4.1 Flash catalog natively
(`dsh-llm-deepseek` DEFAULT_MODELS lists `deepseek-flash` with image
input), which retires Oh-DSH's advisory catalog patch rows — the original
motivation for this branch. But 0.1.5 also breaks three load-bearing
contracts at once: the CLI reserves `--profile desktop` for the official
DSH Desktop app, the client slot graph restructures its root children
(`main` keyed panels, `rightbar`, `provideRoot` panel-info hooks), and
dsh-TUI v0.10.1 renames its update-check seams.

## Decision

- The Electron host boots the runtime through a staged launcher
  (`lib/ohdsh-desktop.mjs`) that resolves the programmatic `runProfile` /
  `runPlugin` entries from the build-hashed lib chunks by prefix — the
  same entries the CLI wraps — so no `--profile desktop` argument is ever
  parsed. The new `ohdsh plugin` subcommand drives profile plugin
  management through the same seam (desktop) or the plain CLI (web/tui).
- The desktop-frame plugin was rewritten onto the 0.1.5 slot contract:
  `main` keyed by the active panel, `rightbar` with width/viewport
  params, the `shell.overlay` list, and a `provideRoot({hooks:{panelInfo}})`
  provider — without it every slot entry calling `usePanelInfo` crashes
  and the client graph dies. The visual layout stayed on the Oh-DSH
  composition (see the Codex finish note for the restyle).
- The three llm-deepseek catalog patch rows and their regression test are
  deleted wholesale: the native catalog is now the single authority.
- Submodules move with the line: dsh-TUI v0.10.1 (adapter seams follow
  notifyChannel and the channel/reports.js split), DSH-better-sidebar
  v0.19.0, dsh-context v0.49.2; workspace overrides mirror upstream
  dsh-TUI v0.10.1's own block.
- The client smoke drives first-run onboarding with Electron trusted
  input events (0.1.5 Radix surfaces ignore untrusted synthetic clicks).

## Alternatives considered

- Keeping a patched `--profile desktop` path: the parser rejects the name
  outright; forking the CLI argument layer would fight every future bump.
- Renaming our profile to dodge the reservation: the marketplace, lock
  files, and user homes all speak `desktop`; the reservation is the
  upstream signal to boot programmatically instead.

## Consequences

- The staged launcher is a build artifact contract: if the runtime
  renames its lib chunk prefixes (`profile-boot-*`, `plugin-*`), boot
  fails loudly at startup instead of silently misbehaving.
- Smoke no longer drives the picker at all: the preload delivers the
  bridge's open-paths command over a pre-seeded workspace storage record,
  so the smoke workspace opens through the same path a folder drop takes
  and the picker's real-input-only behavior never matters.
- nix fixed-output hashes follow the moved sources; the recorded
  temporary-workflow procedure refreshes them (same as the 0.1.2-rc.1
  round).
- Retired catalog rows mean users who pinned a retired model id keep
  working (the endpoint routes them) but the picker no longer offers
  them; `deepseek-flash` is the listed identity.
