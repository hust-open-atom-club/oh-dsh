# Agent Note：将固定 DSH 运行时升级到 0.1.1-rc.2

Status: implemented

[English](2026-08-22-dsh-0.1.1-rc.2-upgrade.md) | 中文

## Problem

Oh-DSH 此前固定在 `@deepseek-ai/dsh@0.1.0-rc.7`。上游发布了
`0.1.1-rc.2`（当前 `latest` 标签），改变了 Oh-DSH 依赖的三处契约：
转发的凭据事件更名；Web 客户端启动图改用新的全局标记注入；
`dsh-client-ui-renderer` 接管了 `document.title`，会在视图和会话变化时
改写为它自己的产品标题。

## Decision

- 将 `dsh-source.json` 重新固定到 `0.1.1-rc.2`（tarball 与 SHA-512 均取自
  npm registry），并从发布装配件自身的解析结果重新生成
  `scripts/dsh-runtime-0.1.1-rc.2-lock.yaml`，删除 rc.7 的 lockfile。
  staging 仍然使用 `--frozen-lockfile` 安装。
- 跟随已发布的表面依赖：dsh-TUI 子模块 → v0.8.8（其自身依赖
  0.1.1-rc.2 包线），Better Sidebar 子模块 → v0.15.0，
  `plugins/vision/package.json` 的 13 个 `@deepseek-ai/dsh-*` 依赖 →
  `^0.1.1-rc.2`。平台覆盖不变：staging 仍从同一个 pin 为 macOS
  arm64/x64、Linux x64、Windows x64 解析各自的 Node 发行版。
- 在最窄的接缝处适配三处契约变化：vision 设置卡中
  `credentials/updated` → `credentials/reference-updated`；smoke 流程改从
  `globalThis["__DSH_BOOT__"]` 读取启动图；Web 外壳改用
  `document.head` 上的 MutationObserver 在渲染器每次改写后重新断言
  `Oh-DSH Web` 标题，而不是一次性赋值去赛跑。
- `stage-dsh.mjs` 以新名字 `dsh-ecosystem-spec` 暂存 TUI 更名后的目录；
  staging 接缝没有其他移动。

## Consequences

- 运行时 lockfile 名仍由 `DSH_SOURCE_SPEC.version` 派生，nix 与 CI 无需
  硬编码版本即可取得新 pin。
- Web 标题从一次性赋值变成持续断言；若 DSH 将来提供产品标题覆盖契约，
  应以该契约替换该 observer。
- 工作区内所有 `@deepseek-ai/dsh-*` 的解析现在都统一在
  `0.1.1-rc.2`。两处仅靠 range 会漂移的地方由 pnpm-workspace 的
  `overrides` 兜底：`dsh-working-activity` 自动安装的 optional peer
  在全新安装时会重新解析回旧 `0.1.0-rc` 线；固定的 dsh-TUI 子模块的
  `dsh-agent-instructions` range 解析不确定。切勿对本 workspace 执行
  `pnpm -r update`：它会改写 `upstream/dsh-TUI/package.json`（固定
  子模块），生成被 CI frozen 安装拒绝的 lockfile。应改用定向的
  `pnpm update <包名>` 加 `pnpm dedupe` 重解析。

## Alternatives considered

- 保持 rc.7 只升子模块：dsh-TUI v0.8.8 依赖 rc.2 包线，表面与运行时会
  分裂；否决。
- 在 staging 中补丁渲染器包来覆盖标题：MutationObserver 把修改留在我们
  自己的 Web 客户端里，且能在上游 bundle 哈希变化后存活；采用后者。
