# Agent Note: DSH 0.1.5-rc.1 升级

状态：已实现

[English](2026-09-11-dsh-0.1.5-rc.1-upgrade.md) | 中文

## 问题

0.1.5-rc.1 发布线原生自带 DeepSeek V4.1 Flash 模型目录
（`dsh-llm-deepseek` 的 DEFAULT_MODELS 已列出带图像输入的
`deepseek-flash`），Oh-DSH 的顾问式目录补丁行随之退役——这是本分支
最初的动因。但 0.1.5 同时打破了三个承重契约：CLI 把 `--profile
desktop` 保留给官方 DSH Desktop 应用；客户端槽位图重构了根子节点
（键控的 `main` 面板、`rightbar`、`provideRoot` 的 panel-info 钩子）；
dsh-TUI v0.10.1 重命名了更新检查 seam。

## 决策

- Electron 宿主通过暂存启动器（`lib/ohdsh-desktop.mjs`）引导运行时：
  按前缀从构建哈希的 lib 分块里解析出程序化的 `runProfile` /
  `runPlugin` 入口——正是 CLI 包装的同一些入口——因此从不解析
  `--profile desktop` 参数。新增的 `ohdsh plugin` 子命令走同一
  seam（desktop）或普通 CLI（web/tui）驱动 profile 插件管理。
- desktop-frame 插件按 0.1.5 槽位契约重写：按激活面板键控的
  `main`、带 width/viewport 参数的 `rightbar`、`shell.overlay`
  列表，以及 `provideRoot({hooks:{panelInfo}})` 提供者——缺了它，
  任何调用 `usePanelInfo` 的槽位条目都会崩溃、客户端图整体死亡。
  视觉布局保持 Oh-DSH 组合（重制风格见 Codex finish note）。
- 三处 llm-deepseek 目录补丁行及其回归测试整块删除：原生目录
  从此是唯一权威。
- 子模块随发布线移动：dsh-TUI v0.10.1（适配 seam 跟随
  notifyChannel 与 channel/reports.js 拆分）、DSH-better-sidebar
  v0.19.0、dsh-context v0.49.2；workspace overrides 镜像上游
  dsh-TUI v0.10.1 自己的块。
- 客户端冒烟用 Electron 可信输入事件驱动首次运行引导（0.1.5 的
  Radix 表面忽略不可信合成点击）。

## 否决的备选

- 保留打补丁的 `--profile desktop` 路径：解析器直接拒绝该名字；
  分叉 CLI 参数层等于跟每次未来升级作对。
- 改名我们的 profile 躲开保留字：marketplace、锁文件和用户 home
  都说着 `desktop`；保留字正是上游"改用程序化引导"的信号。

## 后果

- 暂存启动器是构建产物契约：若运行时重命名 lib 分块前缀
  （`profile-boot-*`、`plugin-*`），启动会在开机的第一时间响亮失败，
  而不是静默走样。
- 冒烟不再驱动选择器：preload 在预置的 workspace 存储记录上投递
  桥的 open-paths 命令，冒烟工作区走与文件夹拖入相同的路径打开，
  选择器只认真实输入的行为不再重要。
- nix 固定输出哈希跟随移动的源；沿用 0.1.2-rc.1 那轮记录的临时
  workflow 流程刷新。
- 目录行退役后，固定了旧模型 id 的用户照常工作（端点仍会路由），
  但选择器不再列出它们；`deepseek-flash` 是列出的身份。
