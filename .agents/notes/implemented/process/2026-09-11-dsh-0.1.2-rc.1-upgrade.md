# Agent Note: Upgrade the pinned DSH runtime to 0.1.2-rc.1

Status: implemented

English | [中文](2026-09-11-dsh-0.1.2-rc.1-upgrade.zh.md)

## Problem

The pinned runtime sat at `0.1.2-alpha.3` because every release after
alpha.3 removed the `Session.events` getter that every released dsh-TUI
read. dsh-TUI v0.10.0 ships the Session-projection adaptation and declares
`0.1.2-rc.1` in its peer unions, so the rc line is reachable again.
Separately, the model-catalog stopgap entry
`deepseek-v4.1-flash-expires-on-0910` embedded its own retirement date and
DeepSeek now serves V4.1 Flash under the official id `deepseek-flash`
(2026-09-10 changelog).

## Decision

- Pin `0.1.2-rc.1` and follow the released surface dependencies on the same
  line: dsh-TUI v0.10.0 (nested dsh-auth 94fdf81; dsh-ecosystem-spec
  d28c267 unchanged), Better Sidebar v0.18.1 (contains the previous
  v0.18.0-alpha.0+59 pin plus 156 commits), dsh-context v0.47.0 — the last
  release on the 0.1.2-rc.1+ matrix (v0.48.0 moved its V3 baseline to dsh
  0.1.5-rc.1, which no released TUI supports).
- Replace the expiring catalog entry with the official `deepseek-flash` id
  (first position, name `DeepSeek-V4.1-Flash`, text+image) in all three
  surface patch layers. The patch layers stay because the runtime's own
  `DEFAULT_MODELS` gains `deepseek-flash` only in 0.1.5-rc.1 (verified by
  unpacking 0.1.2-rc.1, 0.1.3-alpha.2, 0.1.5-alpha.1, 0.1.5-rc.1).
- The TUI patch layer's `llm-deepseek` row restates the TUI bundle's own
  keys (`apiKeyEnv`, `baseURL`, `thinking: enabled`, `reasoningEffort:
  max`) beside `models`: a patch row replaces the row's whole config, and
  the schema has no defaults for thinking/effort, so a models-only row
  silently dropped them on the terminal surface. The contract test now
  pins those keys.
- The TUI remount row `oh-tui-renderer` mirrors the upstream `dsh-tui` row
  inject list including `tuiThemes`.
- Drop the `cc-tui` disabled row (dsh-TUI 0cecfd4 retired the legacy row
  name; v0.10.0's patch has no such row) and its test assertion.
  `TUI_SUPERSEDED_BUNDLES` keeps cleaning the `dsh-cc-tui` bundle from
  user profiles one more cycle.
- Drop the workspace override for `dsh-session-persistence-sqlite`: v0.10.0
  pins it at an exact `0.1.1-rc.2` (no later release exists; rc.1 removed
  the runtime's SQLite backend), and an exact spec cannot drift.
- Adapter seams for the v0.10.0 build: `LogoV2` grew a signature
  (intro/whaleIdle/working) with the whale welcome rework, Chat.js's
  inline-layout flex row gained `marginRight: -pageInsetX`, and
  `LEGACY_DATA_DIR` is gone with the ~/.dsh-cc migration retirement.

## Consequences

- All three surfaces ride one coherent 0.1.2-rc.1 tree (frozen install,
  213 override pins, 214 resolved `@deepseek-ai/dsh-*` packages).
- The catalog patch layers remain a distribution-owned catalog; they are
  deleted wholesale when the runtime line that ships `deepseek-flash` in
  `DEFAULT_MODELS` becomes reachable (0.1.5-rc.1 needs a dsh-TUI release
  declaring it; sidebar v0.19.0 / context v0.49.0 already target it).
- DeepSeek routes the retired `deepseek-v4-flash` /
  `deepseek-v4-flash-vision-exp` ids to V4.1 Flash temporarily and will
  route `deepseek-v4-pro` the same way after 2026-09-14 12:00 CST, so the
  legacy catalog entries are display-only history until the 0.1.5 bump
  removes them.
- Nix: revs and the two npm tarball hashes moved; the fetchFromGitHub nar
  hashes and both fetchPnpmDeps hashes still need a refresh from a real
  `nix build` on a nix-capable host (noted beside the pins in nix/oh-dsh.nix).

## Alternatives considered

- **Pin 0.1.5-rc.1 (npm latest) now.** Rejected: no released dsh-TUI
  declares the 0.1.5 line (peer ceiling `0.1.2-rc.1`), and the 0.1.5 line
  retires plugin contracts (ctx.agent, Inbox class, conversation slot) our
  client plugins still consume — running pinned surfaces against an
  undeclared line is exactly what the 0.1.2-alpha.3 note refused to do.
- **Drop the catalog patch layers entirely.** Rejected for this round:
  0.1.2-rc.1's compiled catalog still lacks `deepseek-flash`; every
  surface would lose the V4.1 entry until the 0.1.5 line lands.
- **Keep the sqlite override at 0.1.2-alpha.2.** Rejected: it would
  override v0.10.0's deliberate exact `0.1.1-rc.2` pin and diverge from
  the upstream workspace.
