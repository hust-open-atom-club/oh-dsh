# Agent Note: 一屏式落地页布局

Status: implemented

[English](2026-08-26-website-one-viewport-landing.md) | 中文

## Problem

落地页的 hero 区带有随视口变化的最小高度和很大的纵向内边距，产品截图又随列宽缩放，
导致页面高度超过典型笔记本视口，页脚必须滚动才能看到。

## Decision

页面外壳改为 `min-height: 100vh` 的弹性列：页眉和页脚是不可压缩的行，`main` 填充剩余高度，
hero 的两列在其中垂直居中。产品边框收缩包裹图片，图片保持宽高比并以
`min(60vh, 640px)` 封顶，截图因此不会把页面顶出视口。hero 间距收紧，
并以 `max-height: 780px` 媒体查询在矮屏桌面上进一步压缩标题、下载按钮和截图。
移动端宽度（≤820px）保持原有的可滚动单列流程不变。

## Alternatives considered

**在 body 上加 `overflow: hidden`。** 不采用：在特别矮的屏幕上会静默裁掉内容，
而不是退化为滚动。

**对截图使用 `object-fit: cover`。** 不采用：会裁掉 UI 截图的边缘；
边框必须展示完整图像。

**hero 使用固定像素尺寸。** 不采用：为了让一屏放下而放弃宽屏的流式设计，
正确的做法是只封顶高度驱动因素。

## Consequences

从 1280×800 到 1920×1080 的桌面视口内，落地页一屏放下、无需滚动，页脚始终可见；
特别矮的视口退化为滚动而不是裁剪，手机端仍然滚动。截图按视口高度缩放，
因此在宽而矮的窗口里不再撑满整个 hero 列——光晕和阴影保留视觉锚点，
由网格间距让文案列居中。

## Testing

在真实浏览器中于 1440×900、1366×768、1280×800、1512×982、1920×1080
测量：每个尺寸下 `document.scrollHeight` 都等于 `innerHeight`（无滚动条），
页脚社区链接都位于页脚正中心（如 1440×900 下 720/720 px）。390px 移动端布局
仍按原样堆叠和滚动。Agent Note 格式、分类与翻译配对门禁通过。
