# Agent Note: Marketplace 展示带缓存的 GitHub 仓库元数据

Status: implemented

[English](2026-08-27-marketplace-github-repository-metadata.md) | 中文

## Problem

Marketplace 卡片通过来源仓库标识插件，但目录本身没有提供描述、star、fork 或最近活动等有用的仓库上下文。如果每个渲染器直接获取这些信息，就会重复网络策略，并把凭证或提供方假设暴露给客户端；网络中断时各目录视图也会不一致。流行度数字还很容易被误认为插件安全可安装的证据。

## Decision

由 host 为 Marketplace 条目获取公开的 GitHub 仓库元数据，并将规范化结果缓存在现有共享数据根目录的缓存中。客户端消费 host 所有的快照，而不是自行调用 GitHub。网络不可用时使用缓存读取；刷新只替换通过校验的元数据。缺失、过期、触发速率限制或格式错误的响应不会把卡片变成安装批准。

展示的元数据属于呈现上下文：仓库身份和 URL、描述、star、fork、GitHub 汇总的开放 Issue 与 PR 数量，以及可用的主要语言、许可证和仓库更新时间。流行度绝不是安全信号或信任授权。安装安全性仍由 Marketplace 来源、溯源、权限、预览、明确批准以及事务／恢复控制决定。GitHub 数值会被明确标注，并且可以缺失或过期；它们不会被转换为排序依据或隐式允许列表。

## Alternatives considered

**由每个客户端表面自行获取 GitHub。** 不采用：Desktop、Web 和其他客户端会重复缓存、错误处理与速率限制行为，也会增加意外处理提供方响应或凭证的代码位置。

**只将仓库元数据放进已发布目录。** 不采用：这样会让目录发布者负责新鲜度，每次元数据变化都需要发布目录；由 host 获取既保持目录身份为权威，又允许受限刷新和离线回退。

**不缓存，只在请求成功后展示元数据。** 不采用：暂时的 GitHub 故障会让 Marketplace 闪烁或丢失有用上下文，反复打开表面也会消耗相同的网络预算。

**按 star、fork 或其他流行度指标为插件排序或批准。** 不采用：流行度可变、可操纵，并且与代码溯源、请求权限或实际行为无关。将其当作信任会把社会指标变成安全边界。

## Consequences

Marketplace 展示获得有用的 GitHub 上下文，同时所有表面共享一套 host 侧获取、校验和缓存策略。缓存值让离线和受限速率时的浏览仍然有用，但代价是必须明确容忍过期或不完整字段，并承担 host 存储和刷新逻辑的复杂度。公开 GitHub 访问仍受可用性和速率限制影响；查询失败时目录必须保持可用。

UI 不得暗示背书：元数据仅供参考，不能绕过来源校验、权限审查、预览、批准或恢复流程。未来的信任或排序功能需要单独的决策和独立的安全模型，而不是复用这些字段。
