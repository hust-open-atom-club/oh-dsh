# Agent Note: 有原生窗口框架时，悬浮控件为会话顶栏让位

Status: implemented

[English](2026-08-28-floating-chrome-clears-session-top-bar.md) | 中文

## Problem

桌面面板工具栏（固定摘要、终端、侧边栏）是固定在 `top: 5px; right: 14px`、
z-index 最大的悬浮元素。macOS 与 Windows 在 `<body>` 上预留了页内标题栏行，
内容从其后开始；而保留原生窗口框架的平台（Linux）不预留任何空间，会话列从
y=0 开始 —— 它的顶栏正好把一个 `Session log` 控件（宽 111px、右内缩 28px）
放在工具栏占据的那个角上。工具栏把它整个盖住：有活动会话时点不到自己的会话
日志按钮，点击被工具栏静默吞掉。

## Decision

`desktop-frame` 在根元素上发布两个关于自身布局的事实 —— 悬浮控件挂在框架
之外，只能从根元素读取：

- `--oh-dsh-details-width` —— 会话详情列当前宽度，折叠时为 `0px`。
- `data-oh-dsh-session-active` —— 存在非空白会话时出现，这正是会话顶栏渲染
  其控件的时机。

侧边工具面板用同样的方式发布第三个事实
`--oh-dsh-workspace-panel-inset`（面板宽度 + 它到右边缘的距离，关闭时为
`0px`），并在最大化时标记 `data-oh-dsh-side-panel-maximized`。**工具栏拥有
右上角**，它的 `right` 只让位给挤压会话列的东西：

```css
min(
  max(
    14px,
    calc(
      8px
      + var(--oh-dsh-details-width, 0px)
      + var(--oh-dsh-workspace-panel-inset, 0px)
    )
  ),
  calc(100vw - 460px)
)
```

挪动的是会话顶栏的 utilities（`Session log` 所在槽位）：在有原生窗口框架的
平台上，它们让出 `--oh-dsh-toolbar-clearance: 89px` —— 即工具栏占位
（95px 主体 + 14px 窗内缩 + 8px 间隙 = 117px）减去顶栏自带的 28px 右内缩，
按钮最终与工具栏保持 8px 视觉间隙。选中 utilities 走稳定的 slot 契约
`[data-slot='conversation.session.header'] :has(> [data-slot='conversation.session.header.utilities'])`，
绝不碰上游的 CSS-module 哈希类名；且只在有活动会话、面板未最大化时生效。

垂直位置也是契约的一部分：有活动会话时工具栏改为 `top: 11px`、按钮 28px，
与 `Session log` 按钮等高、共用中线，而不是浮在它上方半行。

侧边工具面板最大化时独占整行，于是工具栏降到右下角而不是吊在面板中间，
utilities 的让位同时取消（那个角落不再有工具栏）。它保持可见可点：面板头部
只有返回、关闭标签页和关闭三个按钮，没有还原控件。

固定摘要面板只跟随详情列宽度，它本来就落在顶栏下方，且与侧边工具面板互斥。
macOS 与 Windows 保留各自的 `right` 覆盖、也不做让位，因为它们的标题栏行
让冲突不可能发生，动任何东西都只会让工具栏无端偏离角落。

Linux、1282px 视口实测：打开会话时工具栏占 1173..1268（右上角），
`Session log` 在 1054..1165 —— 8px 间隙，两者中线都在 y=28，工具栏下方没有
任何可交互元素；打开侧边工具面板（宽 480）后两者一起左移：`Session log` 到
574..685、工具栏到 699..794 —— 14px 间隙（工具栏相对被挤压列的内缩在两种
状态下差 6px，两者都属于正常控件间距）；面板最大化时工具栏停靠右下角
1173..1268 / y=765，`Session log` 回到自然角落位置。打开详情列时工具栏与
utilities 同步移动，间隙恒定。

## Alternatives considered

**在框架内为有原生窗口框架的平台预留 chrome 行。** 先实现后被否决：Linux
已经渲染了系统标题栏，再空出 40px 只会被读成浪费空间而非 chrome。这是视觉
上最差的方案，已回滚。

**把工具栏下移到会话顶栏之下（`top: 52px`）。** 否决：它会浮在会话内容上
而不是窗口边缘，并且会与从 `top: 48px` 展开的固定摘要面板相撞。

**把工具栏挪到其它角落。** 否决：底边属于终端面板和输入区，而且面板控制条
在各平台都应属于窗口顶边。

**给上游顶栏加内边距让 `Session log` 左移。** 否决：该元素位于上游的
CSS-module 树中，针对哈希类名的选择器会在每次上游发版时失效。

**无条件应用内缩。** 否决：没有会话时顶栏并没有 `Session log` 控件，永久
内缩的工具栏会毫无理由地悬在离角落很远的地方。

**用 `max()` 组合内缩量而不是相加。** 先实现后被否决：侧边工具面板并不覆盖
会话列而是挤压它，`Session log` 会跟着一起左移。取最大值能让开面板，却把
工具栏落在 `Session log` 上，重叠 81px。

**面板最大化时继续用顶部内缩。** 否决，这正是最初的缺陷：面板此时与视口等宽，
`Session log` 被挤到 x=96，`min()` 封顶后工具栏停在 359..460 —— 面板的正
中央，与首次反馈描述完全一致。

**让工具栏让位、`Session log` 保留角落。** 第一版实现并发布后因反馈反转：
右上角读起来本该是工具栏的家，交换后两个控件同处一行、间距稳定。当前决策
改为移动 utilities，也让工具栏的位置不再依赖上游控件的精确宽度。

**面板最大化时隐藏工具栏。** 否决：面板头部只提供返回、关闭标签页和关闭，
没有还原控件，而最大化状态在关闭面板后仍然保留 —— 隐藏唯一的开关会把用户
困在最大化面板里。

**从布局 store 里读面板宽度。** 否决：面板可以被最大化、样式由 CSS 决定，
只有已挂载的元素知道它真实的占位；在该元素上挂 `ResizeObserver` 能在拖拽、
最大化和视口变化后都保持正确。

## Consequences

框架与侧边工具面板向悬浮控件暴露了三个小契约：两个 CSS 自定义属性、两个
根元素属性，以及工具栏上的 `max()` / `min()` 组合和 utilities 槽位上的让位
规则。工具栏拥有自己的角落、不查询任何布局状态，`sidebar` 因此与框架的
store 和面板宽度都保持解耦。89px 让位量是与上游顶栏布局的约定 —— 117px
工具栏占位减去顶栏自带 28px 内缩，脆弱度与早先的 139px 方案相同：上游几何
一变，只需改这一个变量；而基于 slot 契约的选择器能扛住上游重建。面板占位
是运行时测量的，拖拽和最大化都不需要额外接线。`tests/desktop-titlebar.test.ts`
锁定了发布值、让位规则、活动会话下的垂直对齐以及组合后的 `right` 规则，
静默回归会先让测试失败，而不是先坑掉用户的一次点击。
